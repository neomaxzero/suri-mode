# Resume context

Recover enough reliable context to continue the requested work without repeating completed investigation or inventing memory.

- Start with the conversation's available summary and the existing task or human-gate record. Consult relevant repository lessons when they affect the next action. Reuse those records rather than creating another memory file.
- Establish the requested project and topic from context. If the target is genuinely ambiguous, ask a focused question before searching unrelated work. Do not silently narrow an explicit request for broader coverage.
- Search additional history only for a material gap in intent, decisions, approvals, evidence, or unfinished work. Prefer supported task-reading tools and relevant records; do not assume a product-specific transcript path exists or search unrelated private conversations.
- Check current files, branches, PRs, or other relevant live state when the next decision depends on whether a historical result still holds. A prior completion claim is not proof of the current state, and missing history is not proof that an action never happened.
- Distinguish completed and verified work from plans, reported results, and unresolved claims. Preserve the latest applicable user choices and approval checkpoints; a request to recall or summarize does not authorize implementation or publication.
- Return a concise account of what is done, what remains or is blocked, and the next concrete action. Cite the relevant record or artifact when useful and disclose material gaps. If the user asked to continue and authority is already clear, resume the authorized work rather than asking for the same approval again.
- Work directly by default. Use subagents only when bounded independent retrieval justifies its cost under Suri's model policy. Do not sweep every source or replay an entire transcript when the existing context is sufficient.
